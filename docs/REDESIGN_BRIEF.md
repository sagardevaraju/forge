# FORGE — Redesign Brief

**Purpose:** prep document for an `/ultrathink` pass aimed at redesigning FORGE so it survives scrutiny from a panel that mixes industry practitioners (cat-ops VPs, actuaries, reinsurance treasurers) and academic / Industrial Engineering / MEM senior VPs.

Three coupled objectives, in priority order:

1. **UI/UX redesign** — three views must read as senior-executive-grade, not as a hackathon dashboard.
2. **Data legitimacy** — every number on screen must have a defensible provenance and a story for what "real" looks like.
3. **Real-world-gap handling** — the panel will probe what breaks the moment FORGE meets a real carrier; we need a credible answer for each gap, not silence.

This brief is the input to `/ultrathink`. The output we want from `/ultrathink` is a phased redesign plan that addresses every line item below.

---

## 1. Audience map

Four practitioner archetypes will evaluate FORGE. Each has a different BS-detector calibrated to a different layer.

### A. Cat-ops VP (Travelers National Cat / Allstate CAT / Heritage / Progressive)
**What they own:** weekly cat posture, quarterly cat-loss outlook, combined ratio in cat-exposed lines.
**What they'll challenge:**
- "Where would *my* book plug in?" — synthetic 10k is a methodology demo, not an asset.
- "How does this feed our PML/AAL reports to the board?" — needs an exec-readable headline.
- "What's the audit trail when I non-renew 1,200 FL policies and OIR asks why?"
- "Why is the agent free-form? My team needs procedure, not vibes."
- "How does this interact with our Verisk AIR / RMS overnight runs — replacement or supplement?"
- "What's the SLA when NHC advisories drop at 11pm Eastern?"

### B. Chief Actuary / Pricing actuary
**What they own:** loss-cost curves, rate filings, reserving, capital model under NAIC/Solvency II.
**What they'll challenge:**
- HAZUS curves are coarse and don't capture **policy-level loss correlation** within one event. Independent-quantile heads understate portfolio VaR.
- VaR-99 isn't a coherent risk measure. TVaR/CVaR is the actuarial standard.
- Pinball loss + MAE/RMSE is fine for point fit; we need **reliability diagrams** and **PIT histograms** for the quantile model.
- 1,000 equal-weight scenarios under-sample the tail. Industry uses importance sampling and stratified tail sampling.
- `REPRICE_FACTOR = 1.15` is a magic constant. Real repricing follows price-elasticity-of-demand curves and rate-filing constraints.
- Time-stratified CV by year is good, but no AMO/ENSO conditioning means the scenario set will systematically miss climate-regime shifts.

### C. Reinsurance treasurer
**What they own:** treaty design (QS, XS, aggregate XL), cession spend, capital relief.
**What they'll challenge:**
- `CESSION_COST_RATE = {"cede_qs": 0.6, "cede_xs": 0.15}` is fiction. Real treaties price by rate-on-line, attachment, exhaustion, reinstatements, profit commission, terrorism exclusions.
- The current MIP zeroes `cede_xs` from VaR-99 retention as if XS always attaches below p99 — that's a modeling sleight-of-hand. Real attachments are negotiated.
- No reinstatement provisions modeled — a single landfall can exhaust an XS layer.
- Treaty-year mismatch: cat treaties commonly run July 1 → June 30. The MIP horizon is implicitly calendar.
- No fronting, no captive option, no ILS / cat-bond comparison.

### D. Industrial Engineering / MEM senior VP / academic panel
**What they own:** methodology, reproducibility, statistical rigor, decision-science orthodoxy.
**What they'll challenge:**
- "Why a deterministic MIP on a Monte Carlo scenario set? Two-stage stochastic programming or robust optimization is the textbook answer."
- "Where's the column generation / Benders / progressive hedging story for the 10K → 10M policy regime?"
- "Ex-post P&L vs naive is a weak counterfactual. Where are the bootstrap CIs and ablations?"
- "Sensitivity analysis on the budget triple — how robust is the chosen action mix to ±10% perturbations?"
- "What's the formal statement of integrality for the relaxed VRP LP?"
- "Reproducibility: pinned seeds? containerized solver? code + data release?"
- "User study: 3 mock VPs is a usability test, not an evaluation. Where's the inter-rater agreement on the SITREP quality?"

## 2. Current state — credibility weak spots, by layer

### 2.1 Data layer
| Asset | Status | Practitioner-perceived weakness |
|---|---|---|
| 10k synthetic policy book | Generated by `scripts/seed_policy_book.py` | All cat-ops VPs: "show me a real book or a SOC 2 path for ingesting one" |
| NOAA Storm Events 2018–2024 | Real, ingested | Actuaries: peak wind is reported in coarse buckets, MAGNITUDE often null |
| Sentinel-2 chips (10k) | Real, cached locally (~6.5 GB) | IE panel: "Why 256×256? Why these 5 bands? What's the cloud-mask story?" |
| FIRMS active fires | Real-time API (with mock fallback) | VPs: "Hurricane carrier — why fires?" Answer: peril extension; demo includes wildfire-adjacent ops |
| FEMA declarations | Real API (with mock fallback) | Strong as historical context, weak as forecast |
| NHC GEFS perturbation | Hand-rolled (track + wind perturbation) | Actuaries: "Calibrated against what? NHC publishes their own ensemble." |

### 2.2 Model layer
- **CV head:** Prithvi-100M frozen backbone + MLP head, trained on weak labels. Per-dim MAE: `vegetation_density` 0.34, `water_proximity` 0.24, `elevation_bucket` 0.21 — three dims report `null` because no defensible weak label was available. Panel will ask: "what does the model do for those three?"
- **XGBoost loss head:** MAE $7.8k, RMSE $15.0k, CRPS proxy $2.4k on a 128k-row holdout. The CRPS is a **proxy** (3-point pinball average × ⅔), not a true continuous CRPS. Actuary will spot this.
- **Scenario generator:** Mean log-likelihood −3.01 on 5 events. Event observation is `(state, peak-wind bucket)` — full track log-lik is unavailable because `storm_events` doesn't carry tracks. Academic panel will want a real PIT-histogram on track parameters.

### 2.3 Optimization layer
- **Portfolio MIP** at 570 cohorts, 6 actions, <5s solve. Action economics are hard-coded magic numbers (see §1.C).
- **Operational VRP** is an assignment LP. Acceptable for the academic panel *if* we cite the integrality argument for the assignment polytope. Currently uncited.
- **Decision reconciler** is a thin filter. Misses several real reconciliation cases: policy notice-period mismatches, regulatory non-renew batching, agent-channel notification, customer-retention overrides.

### 2.4 LLM agent layer
- Cascading client + 7 tools, NDJSON streaming. Provider-agnostic.
- **No citation / provenance system** — the agent says "Tampa exposure is $X" without surfacing which tool call produced X.
- **No audit log** — every chat is ephemeral. A regulator-facing carrier needs WORM-style logging of any AI-influenced decision.
- **No prompt-injection defense** beyond the system prompt — external tool outputs are concatenated into context.

### 2.5 UI layer
Current views are functional but not executive-grade. Specific deficits per view:

**Portfolio Map (`/portfolio`)**
- Header line is one row of text — no exec card with `total TIV / objective / capital headroom / non-renew budget used`.
- Choropleth has no legend, no color-semantic key.
- Drill-down shows raw action fractions; no plain-English recommendation ("Reprice up 47 cohorts in ZIP3 337; Cede XS the rest").
- No comparison view: "current posture" vs "FORGE-recommended posture" side-by-side.
- No what-if slider: capital budget, cession budget, non-renew cap.

**Event Console (`/events`)**
- Cone overlay is single-advisory; no "delta since last advisory" indicator.
- SITREP panel renders raw LLM markdown — no structured fields (threat tier, lead time, recommended actions per lever).
- Agent chat is verbose vs. the map's sparsity — visual imbalance.
- No mini-map of book exposure under the cone vs. outside.

**Claims Pre-Brief (`/claims`)**
- Table is dense and looks like an analyst's spreadsheet, not a manager's briefing.
- No grouping by ZIP3 / county / customer-segment.
- No "expected adjuster load" rollup tying back to the VRP.
- CSV export only — no API hook to a claims-system mock.

**Cross-view**
- No global navigation breadcrumb / threat-banner ("AL092024 — 5-day cone — advisory #18 — 142 mph peak").
- No data-freshness indicator per panel (when was this number computed; from which feed advisory).
- No "source" footnote per chart linking to spec / model card.
- No persona / mode toggle ("Cat-ops view" vs "Reinsurance view" vs "Field-ops view").
- No print/export-to-board-deck affordance.
- Accessibility unaudited (contrast, keyboard nav, ARIA on the map).

## 3. Data-legitimacy framing — what we need to show

Every number on screen needs three things visible (or one click away):

1. **Source** — feed URL, advisory number, last-refreshed timestamp.
2. **Method** — which model / which Python module / which version produced it.
3. **Confidence** — calibration metric, p10/p90 band, sample size, "synthetic" flag where relevant.

We currently have (1) only for the cone and the fires, partially (2) via the docstrings, and almost no (3) in the UI.

We also need a **trust-tier label** per surface: `LIVE FEED`, `MODEL OUTPUT`, `SYNTHETIC SCAFFOLD`, `RECOMMENDATION`. The Claims Pre-Brief is currently a `SYNTHETIC SCAFFOLD` (heuristic from policy fields) but renders like a `MODEL OUTPUT` — that's the kind of mismatch a senior VP will catch in 30 seconds.

## 4. Real-world-gap inventory

These are the gaps the panel will probe. Each needs a `v1 acknowledgement / v2 path` answer.

### 4.1 Data & integration
- [ ] **Real carrier book ingestion** — `/load` accepts a CSV. Production needs SOC 2 ingestion, schema mapping, PII handling, lineage tags.
- [ ] **Policy notice periods** — non-renew has 60/90/120-day notice rules per state. The MIP recommends an action; the workflow must know when it can be acted on.
- [ ] **Treaty schema** — reinsurance is not "QS vs XS". Need attachment / exhaustion / reinstatement / RoL / commissions.
- [ ] **Multi-peril** — current scope is hurricane wind+surge. Severe convective, wildfire, EQ, freeze need separate damage curves and separate scenario generators.
- [ ] **International** — Caribbean and Canadian hurricane tracks impact U.S. coastal lines (re-stagings, fronting).
- [ ] **OIR / state regulator coupling** — non-renew caps aren't just %; they have ratable-territory and policy-class constraints.

### 4.2 Model rigor
- [ ] **Coherent risk measure** — switch VaR → TVaR/CVaR. Re-state the MIP capital constraint.
- [ ] **Loss correlation** — policy losses within a single event are correlated; current independent-quantile heads understate portfolio risk. Need a copula or a joint scenario model.
- [ ] **Importance-sampled scenarios** — 1k equal-weight scenarios miss the tail. Use tail-stratified or Gaussian-process emulator + importance sampling.
- [ ] **Repricing elasticity** — `REPRICE_FACTOR` should come from a price-elasticity model and rate-filing feasibility.
- [ ] **Calibration plots** — PIT histogram on scenario distributions, reliability diagram on XGB quantile heads.
- [ ] **Sensitivity analysis** — automatic ±10% on every MIP budget input, surfaced as bars next to the action mix.
- [ ] **Stochastic programming variant** — recast the MIP as a two-stage SP or distributionally robust optimization for the academic panel.

### 4.3 Decision lifecycle
- [ ] **Versioned decisions** — every solve is a decision artifact (inputs, model versions, output, operator). Store and diff.
- [ ] **Two-person rule** — non-renew at scale should require two operator approvals.
- [ ] **Operator override** — the UI must support "I disagree with the MIP on cohort X" and capture the rationale.
- [ ] **Rollback** — what happens when a decision is reversed mid-flight (notice already sent vs not).
- [ ] **Audit log** — WORM-grade, regulator-readable.
- [ ] **Post-mortem** — when actuals come in, every prior decision is scored against realized outcome and that becomes the next sprint's calibration data.

### 4.4 Production-readiness
- [ ] **Auth / RBAC** — currently none.
- [ ] **Multi-tenancy** — single tenant assumed; carrier customers will demand isolation.
- [ ] **Performance at 10M policies** — current scale is 10k. Cohort aggregation buys 3 orders of magnitude *if* the cohort count grows sub-linearly; needs column generation / Benders at carrier scale.
- [ ] **Concurrent decisions** — two cat-ops analysts running scenarios simultaneously must not race.
- [ ] **Real-time CV** — currently pre-computed nightly. Real deployment may want on-demand for newly written policies.
- [ ] **Reproducibility** — random seeds are pinned in `seed_policy_book.py` and `train.py`; container / lockfile / model-card needs more discipline.

### 4.5 UX / trust
- [ ] **Source attribution per number** — see §3.
- [ ] **Trust-tier labels per surface** — see §3.
- [ ] **Persona-mode toggle** — Cat-ops VP / Actuary / Reinsurance / Field-ops views compose the same data differently.
- [ ] **Decision narrative** — at the top of every view, a 3-line "what changed since last refresh and why it matters".
- [ ] **Print / board-deck export** — PDF or PNG of the current view with timestamps and provenance.
- [ ] **Accessibility audit** — WCAG AA, keyboard nav, screen-reader on the map.

## 5. What we want `/ultrathink` to deliver

A phased redesign plan that:

1. **Re-architects the UI** with a unified component grammar (exec card · trust-tier label · provenance footnote · what-if controls · persona toggle) and lays out specific changes per view.
2. **Hardens the data story** — for each layer (data / model / optimization / agent), specifies what changes from `magic constant` to `calibrated parameter`, and what changes from `synthetic` to `swap-in-real ready`.
3. **Closes the gap inventory** — every line in §4 gets either an in-scope plan or an explicit "deferred to v2, here's the migration path" note.
4. **Sequences the work** — at least three phases (quick wins · structural · production-readiness) with the credibility lift per phase.
5. **Anticipates panel questions** — one paragraph per audience archetype (§1) with the rehearsed defense.
6. **Calls out the trade-offs** — every "we should do X" is paired with what we lose (complexity, performance, model interpretability, fidelity vs. reproducibility) so the user can override.

`/ultrathink` should be exhaustive, not curated. Bias toward listing every option and explicitly rejecting the ones that don't fit, rather than silently filtering.

---

## 6. Constraints to respect

- **Vercel deployment** — Next.js 16 on Node + Python 3.12 runtimes. Don't propose a new runtime tier.
- **Local DB fallback** must keep working — `forge-local.db` is the dev story.
- **`api_py/` modules must remain importable for tests** as well as wrappable by Vercel handlers. No splitting into a separate service.
- **No new languages.** TypeScript + Python only.
- **License-permissive dependencies only** — no Verisk / RMS bindings, no proprietary SDKs.
- **Synthetic book stays the default** — production-data ingestion is a designed-for-but-deferred capability.
